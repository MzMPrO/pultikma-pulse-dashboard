# PulTikma AI — project rules

Monorepo: `frontend/` (React 19 + TanStack Start) and `backend/` (FastAPI). Lovable is no longer used; there is no Lovable-managed state, and normal git practices apply (no special history restrictions).

- Architecture: React 19 + TanStack Start frontend (`frontend/src/`) and a FastAPI backend (`backend/`, `uvicorn app.main:app`). All scores come from the deterministic scoring in `backend/app/services/scoring.py`; the LLM only chats and explains. Details: `docs/ARCHITECTURE.md`.
- The frontend talks to the backend ONLY through `frontend/src/lib/api` (`import { analyze, chat, … } from "@/lib/api"`): `types.ts` (contract), `client.ts` (fetch + timeouts), `chats.ts` (user id + history), `mock.ts` (+ `mockScenarios.json`, offline fallback with the same format), `endpoints.ts`, `index.ts`. Keep the mock in sync with the backend contract (demo scenarios: Inha 84, Chilanzar 39, Novza 79).
- Frontend layout (inside `frontend/`) is feature-based: `src/routes` (thin file routes: head metadata + a page component), `src/features/landing`, `src/features/scout` (components, `lib/guidance.ts`, `map/`), `src/shared` (components, `map` marker helpers, `i18n`), `src/components/ui` (shadcn, do not move), `src/lib` (api, utils, error helpers). Import with the `@/` alias. Put new code in the feature that owns it; promote to `src/shared` only when two features use it.
- `frontend/src/routeTree.gen.ts` is generated by the TanStack router plugin: never edit it by hand and do not commit line-ending-only diffs.
- Routing uses TanStack Router file routes; app screen is `/app` (`/app/*` redirects to it).
- Maps: `/app` uses Leaflet + MapTiler tiles (`VITE_TILE_URL`, `VITE_TILE_ATTRIBUTION`), loaded lazily and client-only. Only the decorative landing map (`frontend/src/features/landing/map`) can use Google Maps when a browser key is present, over an SVG fallback.
- UI strings on the landing go through `useT()` from `src/shared/i18n` (ru primary, uz falls back to ru); the persisted locale store is rehydrated in `__root` to avoid SSR hydration mismatches.
- Backend layout: `app/api` (routers; `main.py` only wires the app), `app/core` (config, models), `app/services` (scoring, agent, llm, fx, chat_store, texts, geo), `app/repo` (PostGIS or CSV in memory), `backend/data` (CSV dataset + schema), `backend/scripts` (`load_data.py`, `live_data.py`), `backend/tests` (pytest). Never commit `.env` secrets.
- Env files: `frontend/.env` (VITE_* only, public keys, git-ignored; template `frontend/.env.example`), `backend/.env` (secrets, git-ignored), root `.env` (docker-compose vars only). Never commit secrets.
- Frontend build uses `@lovable.dev/vite-tanstack-config` (kept as a preset bundling tanstackStart/nitro/tailwind plugins, see `docs/DECISIONS.md`): do not add those plugins to `frontend/vite.config.ts` by hand. Production build: `NITRO_PRESET=node-server npm run build` -> `node .output/server/index.mjs`.
- Run frontend commands from `frontend/` (`npm install`, `npm run dev`), backend commands from `backend/`. Docs and deploy notes: `docs/`.
- Checks before every commit: in `frontend/` run `npx tsc --noEmit`, `npm run build`, `npx vitest run`; in `backend/` run `.venv/Scripts/python -m pytest -q -p no:warnings`. `main` must stay working.
